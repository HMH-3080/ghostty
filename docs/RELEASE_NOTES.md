# Ghostty 1.3.2 — Arabic/RTL fork (v1.3.2-rtl.3)

Third tagged release of this fork. It refines **paragraph-level bidirectional
text**: any row containing Arabic is now laid out as an RTL paragraph, while a
leading LTR prefix (line number, prompt, English label) stays at the left edge.

Based on [commandlinetips/ghostty](https://github.com/commandlinetips/ghostty)
(commit `653cae7`), which in turn forks
[ghostty-org/ghostty](https://github.com/ghostty-org/ghostty) `1.3.2-dev`.

## What's new in rtl.3

- **Forced RTL for Arabic rows**: a row containing Arabic/Hebrew is reordered
  right-to-left even when it begins with an English label such as
  `CONTROL:` or `- Option:`. Only the leading LTR prefix stays in place.
- **Prefixes stay on the left**: `1:`, `$`, `Hello,` and similar prefixes are
  no longer moved to the right edge by the bidi pass.
- **Arabic text reads right-to-left in those rows**, with English words,
  numbers and paths kept as LTR islands inside the sentence.

## Changes inherited from rtl.2

- **Paragraph direction auto-detected** (`FRIBIDI_PAR_ON`) for Arabic-first
  lines, with correct mixed-word order and right alignment.
- **Decorations follow the visual position**: underline, overline and
  strikethrough are drawn under the reordered glyphs.
- **Installer path rewrite**: desktop entry, D-Bus and systemd units point to
  `/usr/local/bin/ghostty` even when installing from a repackaged tarball.
- **macOS CI** uses the `macos-26-arm64` runner for the Icon Composer asset.

## Highlights

- **Arabic/Hebrew RTL** — connected letters, correct word/digit order,
  mixed LTR/RTL lines work; the UI itself stays LTR.
- **Build fix for Zig 0.15.2 on modern glibc** (Arch/GCC 16):
  the host tools `gtk_blueprint_compiler` and `ghostty-build-data` are built
  with the LLVM linker to avoid the `crt1.o:.sframe` relocation failure.
- **macOS/iOS build fix** — the CoreText shaper hooks now return error unions
  like the shared `RunIterator` interface expects (`prepare`/`finalize`), so
  the Apple targets compile with the RTL changes.
- **Installer** — `install-system.sh` keeps exactly one Ghostty on the
  system, installs to `/usr/local`, and fixes desktop-icon launching under
  dbus-broker.
- **Reproducible build** — `rebuild.sh` (Linux) and a GitHub Actions
  workflow for the macOS app.

## Quick install

**Linux** (Arch-tested, GTK4/FriBidi required):

```sh
tar --zstd -xf ghostty-1.3.2-rtl.3-linux-x86_64.tar.zst
cd ghostty-1.3.2-rtl.3-linux-x86_64
sudo bash install-system.sh "$PWD"
```

**macOS (Apple Silicon):**

```sh
unzip Ghostty-rtl-v1.3.2-rtl.3-macos-arm64.zip
mv Ghostty.app /Applications/
xattr -dr com.apple.quarantine /Applications/Ghostty.app
```

Full instructions: [docs/INSTALL.md](../docs/INSTALL.md).

## Expected bidi behavior

| Line | Paragraph direction | Display |
| --- | --- | --- |
| `السلام عليكم، كيف حالك اليوم؟` | RTL | right-aligned, reads RTL |
| `أنا أستخدم Ghostty على Linux` | RTL | starts right, `Ghostty`/`Linux` stay LTR |
| `1: أنا أستخدم Ghostty على Linux` | RTL after the prefix | `1:` stays left, sentence reads RTL |
| `CONTROL: أنا اسمي محمد` | RTL after the prefix | `CONTROL:` stays left, Arabic reads RTL |

## Recommended config

```ini
font-family = "CaskaydiaMono Nerd Font Mono"
font-size = 14

background = #1a1b26
foreground = #c0caf5
```

> [!WARNING]
> Do **not** force a proportional Arabic font (for example
> `IBM Plex Sans Arabic`) with `font-codepoint-map`. Ghostty renders on a
> fixed cell grid; proportional glyphs spread out and look distorted. Keep a
> monospaced font such as `CaskaydiaMono Nerd Font Mono` (it already contains
> Arabic) or a dedicated monospaced Arabic font such as `Kawkab Mono`.

TokyoNight palette and Windows Terminal-style keybindings are documented in
[FORK_NOTES.md](../FORK_NOTES.md).

## Known limitations

- Mouse selection across RTL text is still imperfect: dragging across mixed
  runs can be off by a cell.
- Some Arabic diacritics (tashkeel) can detach from the base letter
  (e.g. the final `د` in `مُحَمَّد`). This is a shaping limitation of the
  fork, not of the font.
- Neutral characters at run boundaries (for example the leading `~` in
  `~/.config`) follow the paragraph direction, as required by the Unicode
  Bidirectional Algorithm; browsers display them the same way.
- The macOS app is unsigned; Gatekeeper needs a one-time approval.

## ملخص بالعربية

الإصدار الثالث من الفورك:

- **أي سطر فيه عربية يُقرأ RTL** حتى لو بدأ بكلمة إنجليزية أو رقم؛ البادئة
  مثل `1:` أو `CONTROL:` تبقى في أقصى اليسار وبقية السطر تُعرض من اليمين
  لليسار مع بقاء الكلمات الإنجليزية والأرقام والمسارات LTR داخل الجملة.
- **الخطوط والتسطير** تتبع الموضع البصري بعد إعادة الترتيب.
- **لا تستخدم خطًا عربيًا متناسبًا** مثل IBM Plex Sans Arabic مع
  `font-codepoint-map`؛ شبكة الخلايا ثابتة وسيتشوه المنظر. استخدم خطًا
  أحادي المسافة.
- **حزمة لينكس جاهزة** مع سكربت تثبيت نظامي.
- **تطبيق ماك جاهز** (Apple Silicon، غير موقّع).
- **ويندوز غير مدعوم** لأن Ghostty نفسه لا يملك واجهة ويندوز — استخدم WSL2.
